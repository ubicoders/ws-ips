Where ips_track sits.

Each box is its own Rust crate, its own process, its own tmux window. The highlighted box is this folder. A box only talks to the next box through a message, never through code.

Where things live

  • yamlsb.flow.yaml lists the four live modules, the four camera ids and the wires, once. ips_calib runs only in calib.flow.yaml and ips_image_relay only in relay.flow.yaml, so sb up starts neither.
  • yamlEvery module has its own parameters/*.yaml. It is the only place settings come from.
  • protomessages/custom/*.proto defines the two custom messages. Each crate compiles what it uses at build time; the relay compiles the stock ros2 sensor_msgs/Image from the sb vault.
  • genswarmbotix_io/ inside each module is generated by sb. Never edit it.

One run, in order

  • 1sb up builds, then starts cameras, detectors, tracker, viewer. sb up relay starts the same plus the four image relays.
  • 2Once per camera placement: detectors on AprilTag, run ips_calib, restart tracker.
  • 3Detectors back on ArUco. Open rerun to watch.
ips_track · 8 source files · ~2100 lines

Many markers, many cameras, one cube.x1, 90 Hz

Each cube wears five markers. Every marker any camera sees becomes a point in the room. The tracker slides the cube's known shape onto those points with one least-squares fit, smooths the result, and ships it.

Files

src/main.rsLoads params and extrinsics, drains zenoh, runs the 90 Hz tick, builds the roster, publishes, prints stats.
src/cube.rsworkshop stubCube geometry, lift_to_world, and fit_cube: the least-squares fit of the cube shape to every seen marker, with an optional reject-the-worst-marker pass.
src/filter.rsPicks the smoother at start: off, lp, oneeuro, kf. One call: smooth().
src/filter_lp.rsSimple blend: a bit of new, a lot of old. Slerp for rotation.
src/filter_one_euro.rsBlend that loosens when things move fast, tightens when still.
src/filter_kf.rsworkshop stubKalman: position with velocity per axis, orientation as an error-state EKF. Resets after a 0.5 s gap.
src/cam_param.rsThe zenoh queryable that hands out each camera's yaml as JSON.
src/fps.rsSliding-window rate meter.
tests/testlift_to_world, fit_cube, kalman, all on made-up data.

Writes

The latest frame table is not cleared between ticks. A frame is refitted every tick until it goes stale, so the filters see repeats.

A cube with alive = false has no pose fields at all. Readers must check the flag before using the pose.

words that keep showing up

Seven words, plain.

iceoryx2
A mailbox in shared memory. Two programs on the same computer pass a big picture by pointing at it instead of copying it.
zenoh
A post office for small messages. Programs publish to a named key; anyone subscribed to that key gets a copy, even over the network.
protobuf
The packing format for a message. The .proto file is the packing list; each crate generates Rust structs from it at build time.
intrinsics
The lens numbers of one camera: focal length, image centre, distortion. From Kalibr, in camchain.yaml.
extrinsics
Where a camera sits in the room and which way it points: a rotation R and a shift t. Made by ips_calib.
Kabsch fit
Given two lists of matching 3D points, find the one rotation and shift that lay one list on top of the other with the least error. Used twice: for cameras, then for cubes.
rerun
A 3D log viewer. Programs send it points, boxes, images and numbers over time; it draws them with a timeline.
